# Generic embeds

Media-enabled HTML fields accept one iframe with optional external script tags through **Media → Embed external media → Paste embed code**, with no provider whitelist. Pasting an iframe into the editor imports it with sandboxing enabled, even when `paste_html` is off. Pasting iframe-plus-script code opens the dialog for review. Use the accessible title, pasted height and optional proportional video sizing; width always fits the content column. The dialog inserts new embeds. To replace an embed, delete it from the content and paste the replacement.

Embed URLs must be absolute HTTPS URLs. Parsing is inert: surrounding markup, styles and event handlers are discarded; inline scripts, executable URLs and author-supplied `srcdoc` are rejected. Normalized iframe metadata (including ordered, deduplicated script URLs, dimensions and sandbox choice) stays in the existing HTML field's `data-nb-embed` attribute. There is no extra resource or endpoint.

**Sandbox enabled** is the default. Only `manage-unsandboxed-embeds` (also granted by admin `(all)`, absent from ordinary editor permissions) allows disabling it. The role editor lists this capability under System capabilities. Server data validation covers create, update, PATCH and bulk writes, including unmarked iframes. Editors may retain or remove existing unsandboxed embeds while changing surrounding content, but cannot introduce, duplicate, change or move them between fields or languages.

Iframe-only sandboxed embeds preserve the external service's origin with `allow-scripts allow-presentation allow-same-origin`; same-host sources are rejected. Sandboxed embeds with companion scripts render inside a generated outer `srcdoc` document with `allow-scripts allow-presentation`, **never `allow-same-origin`** or top-navigation permissions. Browser sandbox restrictions isolate those scripts from the page. See the [iframe sandbox reference](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox).

Unsandboxed companion scripts use explicit external entries in `collect_external_script($url)`, never the collector's template path. Each context deduplicates URLs in order. Companion scripts load at low priority after `Alpine.start()` announces `nb:ready`; independent load/error handlers continue the queue, and Nimbly startup never awaits them. `[#get-html value embed-preview#]` is the form-field rendering path: it never collects page scripts. Editor and dialog previews always sandbox the iframe and omit companion scripts, with a visible explanation. Providers that refuse framing, depend on page access or require broader sandbox permissions may remain incompatible.
